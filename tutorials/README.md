## Relation to the SigLIP row

This notebook is the fleet's first self-supervised, task-free row and shares its corpus, split, non-neural classifiers and code shape with the SigLIP zero-shot row (`siglip-v1-zero-shot-pipeline`), so the two can be read side by side: where SigLIP scores prompts against photographs, ViT-MAE reconstructs hidden patches and is read through the objective and a linear probe. It keeps the three drawn shapes and their inference contract as Section 5 and carries the adaptation contract around it: a real photograph corpus fetched with per-file pins, a reconstruction protocol in the carried `metrics.py` (masked MSE, visible MSE, hidden-patch PSNR, two fills) and a probe protocol (accuracy, macro F1, per-class, k-NN), a bounded continuation of the pre-training objective with the model's own loss, a per-species breakdown, the shapes re-reconstructed after adaptation, and an artifact that reloads. The per-call `evaluation_report` helper reads a `reconstruct` result; `pipe.evaluate_reconstruction` and `pipe.evaluate` are the corpus-level stages (`measured` / `small-sample`).

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's six modules verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative, replace the `resolve_weights_path` checkout-convenience line and remove internal relative package imports), Section 3 carries the 4-file snapshot manifest inline and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9, MOD12):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries a fresh runtime lacks, at the pinned revision (never `main`); `verify_snapshot` re-hashes every entry and asserts the pinned `model.safetensors` digest and byte count before the model is constructed; `ViTMAEPipeline.from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files (`local_files_only=True`, `trust_remote_code=False`, `use_safetensors=True`) and picks CUDA when it is visible. No cell outside the carried modules calls `huggingface_hub`, `transformers`, `safetensors`, `urllib`, `torch.optim` or the model's encoder and decoder directly.
- **Data (DAT1–DAT9, ST6):** the default sample is 360 research-grade, CC0-licensed iNaturalist photographs of six bird species (60 per species, one per observer), each pinned in the carried `samples.py` by photo id, byte size and SHA-256 and fetched from `https://inaturalist-open-data.s3.amazonaws.com/photos/<id>/medium.<ext>` (about 39 MB); a cached or fetched file is refused on any mismatch, and every record keeps its observation page and observer login. `build_sample_dataset(seed=SPLIT_SEED)` draws 36 / 8 / 16 per species (216 / 48 / 96) and `check_split_disjoint` asserts no photograph (by decoded-pixel digest) is shared. The template adds a second *External access* bullet naming the bucket, the byte count and the CC0 licence.
- **Stages (§4.1):** `fetch_corpus` + `read_corpus` + `build_sample_dataset` / `load_byod_dataset` + `split_dataset` (sample acquisition) → `validate_dataset` per split + `check_split_disjoint` + `observer_overlap` + refusal probes (validation, with three digests) → `validate_inputs` + `reconstruct` / `embed` with sanity checks (seeded masks, the pipeline's masked MSE equal to the model's loss) + `evaluation_report` on the drawn shapes (inference contract) → `pipe.evaluate_reconstruction` with the two fills + `majority_baseline` + `colour_neighbour_baseline` + `pipe.fit_probe` / `pipe.evaluate` with the k-NN and the per-species breakdown (baselines) → `pipe.adapt` (bounded continuation) → `pipe.evaluate_reconstruction` on validation and test + `pipe.fit_probe` / `pipe.evaluate` with the comparison (evaluation) → `reconstruct` + `evaluation_report` on the shapes again (inference) → `pipe.save_artifact` → `ViTMAEPipeline.from_artifact` with the parity assertions (export and reload).
- **Loss semantics (UNC1–UNC4):** the masked MSE is the model's own objective in normalised pixel space — uncalibrated, not a perceptual judgement, mask-dependent — and the probe's scores are a readout, not a classifier; the notebook asserts the pipeline's number equals the model's `loss`, uses the same seeded masks before and after adaptation, and no acceptance threshold ships. The shapes re-reconstructed after adaptation carry a `sample-sanity` verdict that names the missing dispersion.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the mean-patch fill, the blur fill and the frozen model are scored on the same 96 test photographs and the same masks as the adapted model; the majority floor, the colour nearest neighbour, the k-NN and the frozen probe on the same photographs as the adapted probe; every metric is labelled as one seeded split of one sample with no dispersion estimate, and the notebook says explicitly that continued pre-training on 216 in-domain photographs barely moves a converged checkpoint, that the learning-rate sweep found `1e-4` hurts, and that the assertion is on the selector (the kept epoch is never worse than the frozen model), not on a gain.
- **Split integrity (SPL1–SPL8):** the split is seeded and image-disjoint; validation (48 photographs) selects the epoch on the masked MSE under fixed seeded masks and the test split is used for nothing but the final evaluation; observer overlap between splits is printed as an observation, and the notebook states that images from few photographers or sessions must be split by source.
- **Ceilings (VAL6):** `DEFAULT_MASK_RATIO` (0.75), `NUM_PATCHES` (196), `MIN_IMAGE_SIDE` (16), `MAX_IMAGE_SIDE` (4096), `MAX_BATCH` (64), the record bounds (8..20,000), the class bounds (2..100), the 64-character label ceiling and the id pattern are stated in the Prerequisites and printed before the model runs; four dataset refusals and one input refusal are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, one zip is read member by member (no `extractall`) into the runtime and its `labels.csv` records flow through the same validation, image-disjoint split, baselines, continuation, evaluation, export and reload cells (the labels feed only the probe). The expected schema and the privacy guidance are stated in the Prerequisites and in Section 4, and the training split is written to `outputs/vit_mae_pretraining_train.csv` in the same shape.
- Licence: the weights are Apache-2.0 and the notebook, README and card say so; the photographs are CC0 1.0 and are not redistributed — the export records the corpus name, release, bucket, byte count and licence under `corpus`.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.

## Outputs

The default notebook path writes (under `outputs/`):

- `vit_mae_pretraining_train.csv` — the training split's labels table in the BYOD shape
- `vit_mae_pretraining_input_manifest.json` — the inference-contract manifest (schema, ceilings, per-image observations, one recorded rejection finding)
- `vit_mae_pretraining_frozen_<shape>.png` / `vit_mae_pretraining_adapted_<shape>.png` — the three drawn shapes reconstructed before and after adaptation
- `vit_mae_pretraining_evaluation_report.json` — the reconstruction and probe results on test (and the validation reconstruction) for the fills, the baselines, the frozen and the adapted model, the per-species comparison, the adaptation history
- `vit_mae_pretraining_shapes.json` — the drawn shapes' masked and visible MSE before and after adaptation
- `vit_mae_pretraining_adapter/` — `adapter.safetensors` (+ probe head) + `manifest.json`
- `vit_mae_pretraining_result.json` — `NOTEBOOK_SOURCE`, model identity, snapshot, corpus, inference-contract reports, comparison, artifact digest, reload parity, runtime
- `provenance.json`
