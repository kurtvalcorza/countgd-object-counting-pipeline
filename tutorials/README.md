## What the notebook teaches

CountGD counts what a prompt names, and the three prompt modes count different things. The demo scene makes that
visible before any number is read: with the text `blue circle` it counts the circles, with three exemplar boxes
alone it counts every drawn shape, circles and triangles alike, and with both it counts the circles again. The
evaluation then reads the model three ways — how many (count error), whether it counted the right things (point
localisation), and whether its boxes enclose them (box IoU) — on synthetic scenes that carry gold object boxes and
on FSC-147 photographs that carry points. The fine-tune trains on the scenes and is checked on the photographs,
so the notebook shows both what a fine-tune fixes and what it must not break.

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository
  import. Section 2 embeds the repository's eight modules verbatim in topological dependency order (each tagged
  `metadata.dimer.embedded_module`; the only rewrites make the weights root and the `resolve_weights_path`
  checkout convenience working-directory-relative and remove internal relative package imports), Section 3 carries
  the 2-file CountGD manifest and the 6-file tokenizer manifest inline and asserts each against the module's
  constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the
  exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the
  carried modules, the inline manifests, or the inline pins differ from the repository, or when the notebook is
  not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9, MOD12):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only
  the manifest entries a fresh runtime lacks, from the authors' Space at the pinned revision (never `main`);
  `verify_snapshot` re-hashes every entry and asserts the pinned source digest; `CountGDPipeline.from_pretrained`
  audits the pickle statically, converts it once with torch's restricted unpickler, refuses a converted file
  whose digest differs from the pin, and loads it with `strict=True`, picking CUDA when it is visible. No cell
  outside the carried modules calls `huggingface_hub`, `transformers`, `safetensors`, `torch.load`, `pickle`,
  `urllib`, `torch.optim` or the network's builder directly.
- **Data (DAT1–DAT9, ST6):** the synthetic scenes are drawn from seeds in disjoint ranges per split; the 80 FSC-147
  photographs are each pinned in the carried `samples.py` by byte size and SHA-256 and fetched from the Hub mirror
  `isentropic/FSC147` at an immutable revision (a cached or fetched file is refused on any mismatch); only the
  24 test photographs are scored. `check_split_disjoint` asserts no image (by decoded-pixel digest) is shared.
- **Stages (§4.1):** `build_synthetic_dataset` + `fetch_corpus` / `read_corpus` / `build_sample_dataset` or
  `load_byod_dataset` + `split_dataset` (acquisition) → `validate_dataset` per split + `check_split_disjoint` +
  refusal probes (validation) → `validate_inputs` + `count` in three prompt modes with sanity checks +
  `evaluation_report` (inference contract) → `pipe.evaluate` + `mean_count_baseline` + `template_matching_baseline`
  (baselines) → `pipe.adapt` (bounded fine-tune) → `pipe.evaluate` on validation, test and FSC-147 with the
  comparison (evaluation) → `count` on the demo scene again → `pipe.save_artifact` →
  `CountGDPipeline.from_artifact` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** scores are uncalibrated sigmoid similarities and the count is a threshold
  decision at upstream's 0.23; no acceptance threshold ships; the demo re-count after adaptation carries a
  `sample-sanity` verdict.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the mean count, the template matcher and the frozen model are
  scored on the same records as the adapted model; every metric is labelled as one seeded draw with no dispersion
  estimate; the assertion is on the selector (the kept epoch is never worse than the frozen model), not on a gain.
- **Split integrity (SPL1–SPL8):** the validation scenes select the epoch and the test scenes and photographs are
  used for nothing but evaluation.
- **Ceilings (VAL6):** `MAX_EXEMPLARS` (3), `MAX_TEXT_CHARS` (64), `MIN_IMAGE_SIDE` (32), `MAX_IMAGE_SIDE` (4096),
  `MAX_BATCH` (16), `MAX_COUNT` (2,000), the resize to a shortest side of 800 px (longest ≤ 1333) and the threshold
  are printed before the model runs; four dataset refusals and one input refusal are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False`, so the default path never opens an upload dialog; when
  enabled, one zip is read member by member (no `extractall`), checked row by row (relative `file` paths, missing or
  undecodable images, `points` or `boxes` on every row) and flattened, and its records flow through the same
  validation, split (at least 18 images for one category; a short split is named), baselines, fine-tune, evaluation,
  export and reload cells; Section 9 writes per-image predictions for the BYOD test split. Sections 5, 6 and 7
  reload the pinned base when the model in memory was fine-tuned, so a re-run never starts from an adapted model.
- Licence: the weights are MIT and the notebook, README and card say so; the FSC-147 photographs are not
  redistributed — the export records the mirror, revision, byte count and licence statement under `corpus`.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime
  execution requirement; a release review must confirm that a recorded clean run in
  `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to
  `Release-grade`.

## Outputs

The default notebook path writes (under `outputs/`):

- `countgd_object_counting_train.csv` — the training scenes' labels table in the BYOD shape
- `countgd_object_counting_input_manifest.json` — the inference-contract manifest (schema, per-mode observations, one recorded rejection finding)
- `countgd_object_counting_demo_frozen_<mode>.png` / `countgd_object_counting_demo_adapted_<mode>.png` — the demo scene with the predicted boxes, per prompt mode, before and after the fine-tune
- `countgd_object_counting_demo.json` — the demo scene's counts and box F1 per prompt mode before and after
- `countgd_object_counting_evaluation_report.json` — the frozen and adapted results on the synthetic test and validation scenes and on FSC-147, the baselines, the comparison, the adaptation history
- `countgd_object_counting_adapter/` — `adapter.safetensors` + `manifest.json`
- `countgd_object_counting_result.json` — `NOTEBOOK_SOURCE`, model identity, snapshot (source, audit and served digests), corpus, inference contract, comparison, artifact digest, reload parity, runtime
- `countgd_object_counting_byod_predictions.json` — BYOD only: the adapted model's count, boxes, points and scores for every test image
- `provenance.json`
